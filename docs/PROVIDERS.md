# 图片服务配置

工坊通过「模型与连接」对接绘图服务。你需要提供可用的服务地址、对应 API Key，以及模型名称或 RunningHub 资源配置。**没有可用密钥时不能生成图片**；保存设置不会自动提交试画。

第三方服务可以使用，但“能填写同一个 Base URL”不代表所有协议都兼容。请核对服务实际提供的请求方式、图片输入与输出格式，而不只看模型名称。

## 选择协议

| 工坊中的选项 | Base URL 示例 | 服务必须支持 |
| --- | --- | --- |
| OpenAI Images 兼容 | `https://api.openai.com/v1` | Images 文生图；需要参考图时还需支持 Edits 图片编辑 |
| Gemini 原生兼容 | `https://generativelanguage.googleapis.com/v1beta` | `generateContent`，可接收图片并返回内联图片内容 |
| RunningHub | `https://www.runninghub.ai` 或 `https://www.runninghub.cn` | AI 应用或工作流的上传、提交和任务查询协议 |

使用第三方时，把示例地址换成该服务文档指定的根地址，模型名称使用服务商给出的完整图片模型 ID。不要在 Base URL 后面再手动拼接生成端点。

Niji 走「提示词 → 官方平台手动生成 → 导入」路线，不在这三个连接选项中配置，操作见 [使用指南](USER_GUIDE.md#使用-niji-7-角色工坊)。本地 ComfyUI 直连尚未实现；运行在 RunningHub 上的 ComfyUI 工作流已经支持。

## OpenAI Images 兼容

选择「OpenAI Images 兼容」，填写 Base URL、模型名称、API Key、生成尺寸和同时生成张数。

工坊会根据是否有参考图选择请求：

- **没有参考图**：调用 `/images/generations`，用于从文字开始设计角色。
- **有参考图**：调用 `/images/edits`，以 multipart 上传参考 PNG，用于基于已有角色生成角色图、母版或表情。

服务需要按 Images 格式返回图片数据或可下载的图片 URL。只提供 Chat Completions 生图、网页结果、自定义 JSON 或只有文生图的接口，不能直接当作完整的 Images/Edits 服务使用。

单参考图使用 `image` 字段；双参考图按顺序使用重复的 `image[]` 字段。第三方服务若支持单图但不支持双图，请选用能接受当前参考配置的模型或服务。工坊不会因请求失败而自动丢掉参考图、改成纯文字或另付费重试。

尺寸选项只是请求参数，实际支持范围由模型决定。先用服务商支持的一个尺寸和较低并发完成单张验证，再批量生成。

## Gemini 原生兼容

选择「Gemini 原生兼容」，填写原生 REST 根地址、图片模型 ID 和 API Key。工坊使用 `/models/{模型}:generateContent`，以 `x-goog-api-key` 发送密钥。

请求包含文字和可选的内联 PNG 参考图，并要求图片输出。没有参考图时用于文生图；有参考图时，模型需要支持图片输入与生成。工坊从 `generateContent` 响应的候选内容中读取内联图片。

确认第三方实现的是这套原生协议，而不是同名模型的 OpenAI Images 包装、聊天端点或其他交互接口。返回一段文字或普通图片链接而没有兼容的内联图片内容，工坊无法按该协议取图。

界面中的 `1K / 2K / 4K` 对应图片尺寸请求；横向或纵向选项会指定相应比例。是否支持这些大小和比例仍取决于所选模型，不能把请求值当作保证输出的像素尺寸。

## RunningHub 应用或工作流

选择「RunningHub」，使用站点根地址，不加 `/v1`。需要准备：

1. 对应站点的 API Key，以及完整的 AI 应用 ID 或工作流 ID。
2. 接收工坊提示词的节点 ID 和字段名。
3. 制作母版或表情所需的角色参考图节点。
4. 可选的第二参考节点，用来接收 Q 版母版。
5. 资源要求的其他节点值，以及从 `0` 开始的输出图片序号。

这些值必须来自**你所选资源**的 API 示例或工作流配置，不能把其他工作流的节点编号直接套过来。模型、采样、宽高和工作流内部批量数由工作流控制，工坊通用尺寸选项不覆盖它们。工坊每个任务只保存你指定的一张输出。

如果工作流只提供文字输入，就不能用来完成要求参考图的母版和表情生成。正确映射输入也不等于模型一定能锁定角色，仍需先试一张检查效果。

收到远程任务号后，工坊会保存该编号并查询结果。连接中断后，有编号的任务可以「继续查询原任务」，无需重新提交绘图；该操作沿用原任务的站点与配置快照。状态不明且没有编号时，先在 RunningHub 核对记录。

这里对接的是 AI 应用／工作流协议，不是 RunningHub 的所有标准模型专用端点。节点映射、任务恢复和故障细节见 [RunningHub 说明](RUNNINGHUB.md)。

## 参考图如何使用

母版和角色表情需要服务实际具备参考图能力，不能只依赖文字描述来保留角色。

在「沿用原图服装」模式下，制作表情时：

- 原始角色图优先提供身份与服装依据。
- 原图与 Q 版母版都已选定且不同，OpenAI/Gemini 请求会同时发送两张，母版提供画风与脸型参考。
- RunningHub 的主参考节点接收原图；配置第二节点才会再发送母版。没有第二节点时只发送原图，画风由提示词补充。

「按文字换装」使用用户填写的新服装；表情请求有母版时使用母版作为单张参考，否则使用原图。角色图与新母版生成使用原始角色参考图。选择模式后，确认预览与候选，再开始整套生成。

参考图缺失、上传失败或服务不支持所需输入时，会显示错误，不会静默退成不带参考的生成任务。

## 密钥、并发与首次试跑

密钥保存在工作室服务端设置中，不包含在浏览器返回的设置、项目配方或 ZIP 中。已有密钥时，在同一连接配置中留空会保留它；更换协议或服务地址后，需要重新填写对应密钥。界面也提供清除已保存密钥的选项。

同时生成张数可设为 **1–4**。首次配置建议设为 1，依次检查：服务接受请求、图片能取回、角色与服装正确、文字方式符合预期，再提高并发或扩大选款。保存连接成功只说明配置被保存，不代表已经通过服务验证。

绘图请求提交后，网络中断不代表平台没有执行。取消本地等待也无法保证停止计费。普通重试会创建新请求；修改当前角色设定后，应从表情选项新建任务应用新方案。RunningHub 已有任务号时优先继续查询原任务。

## 连接问题排查

| 表现 | 优先检查 |
| --- | --- |
| 401 / 403 | 密钥是否属于该站点、模型或资源是否开放给当前账号；更换地址后是否重新填了密钥 |
| 404 / 路径错误 | 选择的协议是否正确，Base URL 是否重复带了生成端点，模型 ID 是否准确 |
| 400 / 参数错误 | 模型支持的尺寸、参考图数量和编辑字段；RunningHub 节点 ID、字段名及必填值 |
| 429 / 额度或频率受限 | 降低并发，检查服务配额与账号限制，再手动重试 |
| 文生图成功，表情失败 | 服务是否支持图生图、multipart Edits 或 Gemini 图片输入；是否支持当前双参考图请求 |
| 服务未返回图片 | 所选模型是否有图片输出，响应格式是否兼容，以及平台是否过滤了本次内容 |
| 网络中断、超时、5xx 或结果不明 | 先查供应商任务记录；避免直接重复提交。RunningHub 有任务号时继续查询 |
| RunningHub 图片不对或尺寸不对 | 输出序号是否指向正确图片，参考节点是否真的参与生成，宽高是否由工作流另行设置 |

部署地址、访问保护和数据备份见 [部署说明](DEPLOYMENT.md)。
