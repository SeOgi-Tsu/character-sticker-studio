# 反应库策划与 Niji 7 参数核查

核查日期：2026-09-08。本文记录产品策划依据，不是 QQ 表情使用量报告。

## 关于“2026 最流行、使用最多”

首版的 48 张是**结合当前公开社区样本和聊天场景的编辑精选**。没有取得 QQ 的表情发送、独立使用人数、转发链或留存数据，因此不能把它们称为“2026 使用最多的 48 张”，也不能承诺传播结果。原来规划的 24 张同样没有这种排名依据。

选择方法是：先覆盖一眼可读的情绪反应，再保留角色辨识度和软萌视觉；优先大头、歪头、探头、鼓脸、贴贴、水汪汪、眼神死、假哭、拍桌等能直接回应群聊的动作。蠕动、融化、打滚等动态语言在本版转换为**一个可读的静态瞬间**。这些具体动作、配文与分组由本项目原创编写；未下载、描摹或打包第三方角色表情图片。

“可爱”和“实用”在首版都是策划判断，尚未通过真实出图后的用户投票或发送数据验证。`recommended` 只表示编辑优先试做。`sourceIds` 只说明相关反应类型的来源线索，不表示素材授权，也不表示这张卡是某个热门表情的复刻。

这里的“菲比”参考对应《鸣潮》角色的社区表情，“塔菲”参考对应虚拟主播社区；两者用于理解反应类型和使用方式。**生成提示词不自动添加这些角色或主播的名字、服饰和面部特征**，目标始终是用户自己的角色。

## 首版反应库的安排

| 套餐 | 数量 | 选择理由 |
| --- | --- | --- |
| 贴脸可爱 12 | 12 | 第一次试做首选：大头近景、柔软脸颊、关心、撒娇、贴贴。 |
| 群聊发疯 12 | 12 | 表情反差更大：眼神死、假哭、蠕动、拍桌、打滚、融化、吃瓜。 |
| 日常好用 24 | 24 | 8 张可爱、4 张强反应、12 张基础回应；兼顾群聊和日常对话。 |
| 完整反应库 48 | 48 | 四类各 12 张全部开放勾选；用户可以删除、改动作、改配文。 |

三种视觉方向分别是奶油精致 Q 版、欠欠大头反应、糯米团子简笔。**一套只用一个已选择的风格**，先确认 Q 版母版，再在相同母版基础上变动作。奶油、珊瑚和鼠尾草绿仅是辅助色，不能覆盖用户角色本来的发色、瞳色与服饰主色。

图片生成和配文分离：提示词要求单角色、单反应、单张图、不画文字；配文在导出阶段叠加。这样改“啊？”为“哇袄”无需重新付费出图，也减少中文生成字形错误。是否有真实透明通道由生成结果决定；提示词不能保证透明度，更不能把棋盘格图案当作透明背景。

后续如果要做有依据的排序，可以邀请用户主动评价“小图可读 / 像不像原角色 / 可爱程度 / 想不想发”，并单独记录实际使用反馈。不同角色、风格和群聊关系应分开观察。首版不包含这种统计功能，也没有隐藏采集。

## Niji 7 技能整合

采用本机 `anime-character-sheet-prompter` 的角色设定结构：角色概念与身份特征先写；再写正、侧、背三视图、头部近景及服饰细节。补充 `midjourney-prompt-engineering` 的具体视觉描述原则。技能原文中部分参数是旧版本混用，代码依据当前官方资料保守修正。

- 默认 `detail` 是三视图加大头及服饰细节：`--niji 7 --ar 16:9 --s 160`；`turnaround` 只包含正、侧、背三个全身视图。`160` 是本产品选择的起点，不是官方最优参数保证。单张全身立绘使用 `--ar 2:3`。
- `raw` 默认关闭，可选 `--raw`。Niji 官方的 [2026-01-26 提示词指南](https://nijijourney.com/blog/niji-7-prompting) 实际展示了此参数，并强调具体描述和更精确的提示词遵循。
- 可选 `--sref`，接受一个数字风格代码或单个 HTTPS 图片链接。官方 [2026-07-08 Style Explorer / Creator 说明](https://nijijourney.com/blog/style-creator) 提供了 Niji 7 风格探索流程。风格参考不会保证身份一致。
- 不自动拼接 `--oref`、`--cref` 或 `--q 2`。Niji 7 不能套用普通 Midjourney V7 的全部特性；本产品不对未启用参数做质量保证。版本能力应再次核对 [官方版本说明](https://docs.midjourney.com/hc/en-us/articles/32199405667853-Version) 和 [Niji 7 发布说明](https://nijijourney.com/blog/niji-7)。
- 用户简介保留原语言，包括中文。这里是本地确定性的提示词整理器，没有隐藏的语言模型翻译步骤，也不会虚称已经把剧情完整分析成角色设定。
- 数字风格化参数限制为整数 0–1000。风格参考拒绝空白、额外命令、权重串、非 HTTPS 协议和带账号的 URL；人物简介中的参数和排列组合控制符会被中和，避免复制后意外增加任务。

本工具只提供 Niji 提示词和出图导入流程。Midjourney 的 [官方社区规则](https://docs.midjourney.com/hc/en-us/articles/32013696484109-Community-Guidelines) 说明其 API 仅有少数明确授权的例外，并禁止未授权自动化。因此第一版没有伪造“官方 Niji API”，也不通过浏览器脚本代发付费任务。

## 验证记录

`tests/prompts.test.ts` 使用 Node 的测试框架验证：套餐引用与数量、来源 ID、固定风格与身份信息、独立配文、母版/三视图结构、Niji 布局和默认参数、风格参考与用户文本的参数注入边界。执行 `node --experimental-strip-types --test tests/prompts.test.ts`，8 项通过。这里没有运行任何付费生成，也没有把提示词测试冒充真实画面质量验证。
