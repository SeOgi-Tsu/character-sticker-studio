# 绒绒工坊 · Character Sticker Studio

从一句角色描述，到一整套属于你的可爱表情。

**v0.6.0** · 独立运行的角色与静态表情创作 WebUI：角色卡、Niji 7 设定图提示词、原服装锁定、参考母版、70 张可选反应配方、七类构图、六种互动、三档张力、表情人格与可选小剧场、三种逐张文字模式、六种字样、云端/RunningHub 批量生成与 ZIP 导出。无需安装 VCP，也无需安装 Codex Skills。

## 启动

需要 Node.js **22.13 或以上**（使用 Node 内置 SQLite）。Windows、macOS、Linux 使用相同命令：

```sh
npm ci
npm run build
npm start
```

访问 [本地工坊](http://127.0.0.1:4317)。开发模式使用 `npm run dev`，前端端口为 5178。

数据保存在 `data/`，配置、角色、图片与生成记录在重启后保留。整个源码目录可以独立移到其他位置。数据目录不包含在源码发布包中；迁移个人数据应停机后单独备份整个数据目录。

## 第一次制作

1. 在「角色设定」填写姓名、描述、性格与不可改变的外观特征，上传已有立绘；可用「表情人格简要」补充她怎么逗人、逞强或偷偷关心。服装默认沿用原图，只有主动选择「按文字换装」才使用文字改变服装。没有立绘时按文字设计，可用云端文生图或 Niji 提示词制作。
2. 在「Niji 角色图」选择立绘、三视图或三视图＋大头细节。复制提示词到官方生成，选好图片后导回工坊。
3. 选择 Q 版风格；可生成母版，也可直接上传已有 Q 版图。角色参考和 Q 版母版分别保存。
4. 在「表情工坊」勾选反应卡，逐张选择「无字」「后期排字」或「随图生成」。展开「镜头、互动与动作」可改构图、张力与接收者感受；「一张图的小剧场」可选填一个处境和露馅细节。保留「可爱犯规 12」「百变可爱 12」「嘴硬小剧场 12」等旧套装，新增「角色小剧场 12」。先选少量不同关系、景别与文字模式验证，再生成整套。
5. 在设置中填写云端供应商协议、Base URL、模型与 API Key。密钥仅保存在本机服务端，不进入前端构建或配方导出。
6. 生成后逐张检查角色、服装和文字。干净源图可以自由切换后期字体、位置或关闭排字；随图生成的文字已经画在原图中，改字或去字需要创建新的生成任务。确认后导出 PNG/ZIP。真实透明图保留透明通道；白底图明确作为白底处理。

默认角色文字以 Margaret 为示例；开源源码不携带用户的私人角色立绘。没有参考图时页面会引导上传，未配置云端接口时不会伪造生成结果。

## 服装与三视图保持一致

「沿用原图服装」固定原图里的服装种类、领口轮廓与深度、开衫的开合、肩袖设计、内外层次、下摆、腿部服饰和配件。Q 版可以简化画法，但不会自动把开衫改成套头衫、加高领口或改变遮盖范围。服饰文字用于补充细节；「按文字换装」是用户明确选择的改装模式。

有原图和母版时，默认表情请求按顺序发送两张：原图负责身份与服装，母版负责脸型与画风。原图对服装的优先级更高。OpenAI/Gemini 兼容接口需支持多图；拒绝多图时会报告错误，不自动以另一张图重新付费生成。只上传了一张时仍可用单图。

RunningHub 主参考节点接收原图；配置可选第二参考节点时再发送母版。未配置第二节点的工作流只收到原图，画风由提示词补充。历史任务的重试仍复用旧快照；修正角色服装后，请从表情选项创建新任务应用新规则。

V4新增「全身半身互动12」类选集：6张全身、6张半身，保留此前所有套装和56个反应ID，另加递茶、踮脚挥手、小个子撑场、半身思考嘴硬4个配方。

## 每张表情，单独决定要不要字

v0.5.0 不再要求整套表情采用同一种底部字幕。点击任意卡片，在「这张，要怎么说？」中选择：

| 模式 | 生成与预览 | 后续修改 |
| --- | --- | --- |
| 无字 `none` | 提示模型生成无文字图片，导出时不添加后期文字；适合摸头、捏脸和动作已经说清楚的画面 | 保存的文案仍保留，可以切回后期排字 |
| 后期排字 `overlay` | 先生成干净源图，再在本地排字；可改字样、配色、上下左右位置、换行、字号与倾斜 | 保存后可查看准确排字成品，也能关闭排字；旧版普通干净源图同样适用 |
| 随图生成 `generated` | 把准确文案、文字画法和布局写进图片提示词，让文字与角色动作一起构图 | 文字是图片的一部分，不能靠关闭排字去除；改字或无字版本需按新方案重新生成 |

随图生成不会在图片上重复覆盖后期字幕。从普通成品切换到这一模式时，预览先显示干净原图，文字在下次生图时画入；已有原生带字图则始终显示实际原图。文字大小以约占画面高度的比例提供给模型，不保证逐像素精确。中文可能出现错字、缺字或不理想的排版，需检查后重生；工坊没有把模型输出当成已校对的文字。

想去掉原生文字时，选择「无字」，再点「按当前方案再画一张」。这会创建新的图片版本，并可能再次产生供应商费用；「使用原任务配方重试」沿用原任务快照，不会应用新的文字或服装设置。

### 六种字样与真实字体

| 字样 | 实际字体 / 处理 |
| --- | --- |
| 经典粗描边 | 系统中文无衬线回退，保留旧版粗描边外观 |
| 快乐软糖 | ZCOOL KuaiLe，圆润不规则的字形 |
| 随手碎碎念 | Long Cang，适合手写吐槽与小声旁白 |
| 毛笔炸毛 | Zhi Mang Xing，适合短句与有力笔势 |
| 软萌对话泡 | ZCOOL KuaiLe，加紧凑浅色气泡 |
| 漫画重击 | ZCOOL KuaiLe，强调色与偏移阴影 |

选择字样会应用对应配色、字号和倾斜预设，保留文案、文字模式与位置；这些参数之后仍可编辑。推荐每张只保留一个短包袱，通常 2–8 个字；无字、手写小声旁白与大字吐槽可以混搭。

三款中文字体及各自 **SIL Open Font License 1.1**、来源与校验记录放在 [public/fonts](public/fonts/README.md)，源码包与 Docker 都会携带，使用这三款字无需在系统中安装字体。字体许可证独立于项目 MIT 代码许可证。它们是本项目选用的排字字体，不代表已识别出鲸鱼娘参考图使用的具体字体；也不能仅凭位图判断参考图的文字是后期添加还是模型生成。

## 表情人格与嘴硬小剧场

「表情人格简要」是可编辑的角色性格说明，最多 1200 字。三个预设「嘴硬小恶魔」「软乎乎的认真派」「淡定吐槽役」只会把明文简介填入编辑框，用户可以继续改写，不会更换服装或覆盖外貌特征。它描述角色的动机、说话节奏、习惯动作与喜剧反差，在下次生成时生效。

Margaret 的示例把「嘴硬小恶魔」表达为成年角色的爱逗人、好胜、炫耀、被识破时破功，以及假装顺手的关心。重点是角色表演和互动，不把性格标签直接当作年龄、身体或服装指令。

V5 的「嘴硬小剧场 12」沿着挑衅、破功、小小得意、偷偷心软组合全身、半身和道具互动；推荐搭配为 **4 张随图生成、4 张后期排字、4 张无字**。其中新增「小小挑衅一下」「刚放完狠话就破功」「赢一点就要炫耀」「才不是特地留给你的」4 个配方，形成原有 **64** 张反应库。套装推荐不会覆盖已经保存的单张文字设置，实际搭配以你自己的选择为准。

## V6：一张图的小剧场

新增「角色小剧场 12」：6 个小处境与 6 张已有可爱反应混合，包括偷吃露馅、替你保管、罐盖僵局、假装路过、偏心打伞、留着你的位置。完整反应库为 **70** 张，旧 64 个配方、原服装规则和 Niji 三视图流程保留；升级不会自动扩大默认选中数量，也不会强制替换已有单张方案。

在角色人格卡下面，可填写最多 **400 字**的「专属小道具与符号」`signatureMotifs`，例如用原有黑蝴蝶结或金色心形呼应点心、抱枕等小道具。留空不增加此方向；它只影响之后的表情道具与表演，不更改衣服、身体或身份。

单张的「一张图的小剧场」提供启用开关和三个字段：**发生了什么** `setup`（240 字）、**露馅的小细节** `reveal`（240 字）、**关键道具** `prop`（160 字）。接口保存为包含 `enabled/setup/reveal/prop` 的完整对象。至少有一项非空才会加入小剧场方向；关闭只把 `enabled` 设为 `false`，保留文字，并停止附加这些剧情描述。

小剧场是一张图里的一个瞬间，用姿态、关键道具和反差让人一眼明白；不会自动扩展成两格漫画、长剧情或满背景场景。修改只用于下一次生成，现有成品保留。文字仍独立选择无字、后期排字或随图生成，原生文字的改字／去字规则也不变。

每个项目仍可添加最多 64 个自定义反应；保存的 `selectedIds` 与生成请求显式传入的 `reactionIds` 上限为 **200**，足以选择 70 个内置配方加 64 个自定义反应。这是接口容量，不代表会自动全选或提交 200 张。

本轮以用户纠正后提供的两张鲸鱼截图作为主要方向，并补充观察了 hololive 官方 VTuber 贴图中大小景别、姿态与简短文字的混搭。具体依据与边界见 [V6 参考记录](docs/V6_REFERENCE_NOTES.md)：学习角色关系与可读的笑点，不把参考图片当作传播量排名，也不把参考角色的道具、服装或台词直接搬进项目。

## 什么是“流行可爱”

内置反应卡是结合公开社区案例和聊天场景进行的**编辑精选**，不冒充 QQ 官方统计、全网热度榜或使用量排名。构图包括贴脸特写、半身互动、全身姿态、夸张全身动作、道具互动、迷你情境和边缘探头。可以混合跑来、抱抱、送花、横躺、打滚、小工位等，不再只用同一个头像换表情。

每张卡片显示构图和互动类型，已选列表显示整套搭配。点开卡片可以分别调整：

- **构图**：特写、半身、全身、动作、道具、情境、探头。
- **互动**：自在反应、扑向你、递给你、摸摸贴贴、软脸压扁、反差发癫。
- **张力**：自然、明显、夸张；增强合适的透视、姿态或大小反差，不自动把每张变成大头。
- **想让对方的感受**：例如想接住、想安慰、被嘴硬逗笑，最多160字。

发型、瞳色、饰件与画风保持一致，机位、裁切、姿势和画面占比单独控制。只有需要接触的模式才允许一只必要的画外观众手；普通反应不会自动多长手。构图、动作、人格与服装修改影响下一次生成，已有图片保留；普通干净源图的后期排字可以直接修改。

完整来源和适用边界见 [调研记录](docs/RESEARCH.md)。案例用于理解情绪和表达方式，不内置搬运的菲比、塔菲或其他创作者图片。

V3进一步参考了2026年7月鲸鱼娘的静态案例，提炼前景手势、大小反差、主客关系与“处境和表情不一致”的笑点。具体实看图源和原创演绎边界见 [静态互动研究](docs/V3_STATIC_RESEARCH.md)。旧塔菲材料仍仅作为历史参考，不冒充当下热度证据。

## 图片接口

| 协议 | Base URL 示例 | 用途 |
| --- | --- | --- |
| OpenAI-compatible Images | `https://api.openai.com/v1` | `images/generations` 文生图；`images/edits` multipart 参考图生成 |
| Gemini generateContent | `https://generativelanguage.googleapis.com/v1beta` | 文字＋内联参考图，解析图片响应 |
| RunningHub 应用 / 工作流 | `https://www.runninghub.ai` 或 `.cn` 站点 | 上传参考图、节点映射、任务提交与恢复查询 |

模型名称可自由填写，需与你的供应商文档一致。相同的 Base URL 配置方式不表示每家服务都支持同样的模型、图片尺寸或参考图字段。第一版不把 Chat Completions 生图代理当成 Images 协议，也不把 Gemini Interactions 当成 generateContent 协议。

一张表情对应一次图片任务。表情任务必须带参考图；沿用原衣模式优先原始角色图，并可同时传入 Q 版母版。母版不覆盖原服装，也不锁定姿势、机位或裁切。参考图失败会明确报错，不降级为纯文生图。请求提交后若网络断开、结果不明，任务进入「状态不明」，不会自动重复提交付费请求。新生成保留旧版本。

RunningHub 需要填写实际应用/工作流 ID、提示词节点和参考图节点；宽高和其他参数由所选工作流控制。收到远程任务号后先保存再查询；有任务号时使用「继续查询原任务」，避免再次生成。当前实现是 AI 应用/工作流协议，RunningHub 标准模型专用 API 不是同一协议。详细配置和已核实接口见 [RunningHub 说明](docs/RUNNINGHUB.md)。

API Key 留空会保留现有密钥；更换服务地址或协议会清除旧密钥，避免误发给另一个服务。取消正在运行的任务属于尽力中止，无法保证供应商未计费。

## Niji 7 的实际边界

整合了角色功能、身份特征、服装、三视图、大头细节和风格的模板结构。参数根据当前 Niji 7 官方说明生成；默认不加入未确认的 `--oref`，也不使用 Niji 7 不支持的 `--cref`。Raw 和 Style Reference 可以选配。

Niji 第一版是**官方生成后导回**的流程。Midjourney 没有面向普通开发者的通用开放 API，工坊不抓取账号 Cookie 或提供虚假的“官方自动生图”。

- [Niji 7 官方介绍](https://nijijourney.com/blog/niji-7)
- [Niji 7 提示指南](https://nijijourney.com/blog/niji-7-prompting)
- [Midjourney API/自动化说明](https://docs.midjourney.com/hc/en-us/articles/32013696484109-Community-Guidelines)

## Docker 与网站部署

复制 `.env.example` 为 `.env`，设置一个足够长的 `STUDIO_TOKEN`，然后：

```sh
docker compose up --build -d
```

Docker 包含中文字体，默认通过 `127.0.0.1:4317` 访问。首次访问输入自己设置的工作室口令。自托管网站应在前面加 HTTPS 反向代理；服务端的允许来源/主机配置请见实际启动日志和 `server/index.ts`。

这是个人工作室，不是多用户 SaaS。GitHub Pages 不能独自运行 SQLite、后台任务和保密 API Key；需要 Node/Docker 后端。移动端可以访问部署好的网页。

## 导出与复现

- 配方 JSON 保存角色、表情人格、专属道具、小剧场（含已关闭的内容）、反应、动作与每张的文字模式和排版配置；导入时清除旧设备的本地图片 ID，重新选择参考图。
- 图片 ZIP 包含 `originals/` 原图、`resized/` 指定尺寸原图、可选 `captioned/` 按单张设置导出的成品、预览联系表和配方；每个表情选取最新的成功版本。原生带字图片在所有目录中都保留内嵌文字，`resized/` 不等于无字图，关闭「附上排字成品」也不会擦除原图文字。
- ZIP 配方附带结果记录中的 `textMode` 与原生文案 `generatedText`；它们用于记录实际生成方式。导入项目配方不会自动恢复图片任务，迁移成品仍需保存图片；通过 API 导入已有带字图时应明确标记 `textMode: "generated"`。
- 存档记录提示词、供应商/模型及输出。云端模型升级或随机性可能改变重新生成的结果；保留母版与成品才能准确保留原画面。
- PNG 尺寸属于工坊导出选项，不意味着已经满足 QQ 表情商城投稿要求。第一版为静态 PNG，尚无 GIF 动画生成。
